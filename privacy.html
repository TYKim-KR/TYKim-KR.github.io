Privacy Policy

ty-assistant · effective 3 September 2026

ty-assistant is a private, self-hosted assistant operated by one individual for their own use. It has no other users and no public sign-up. This policy explains what data the app touches and what happens to it. See the home page for what the app does.

1. Data the app accesses

  • Google Calendar events — read-only, through calendar.readonly. Used to answer schedule questions and to compose a daily briefing.
  • Google account email address — through openid and userinfo.email. Used only to label which account was connected.
  • Messages the owner sends the app — through Telegram.

The app does not request write access to Google Calendar and cannot create, change, or delete calendar entries. It does not access contacts, files, or mail.

2. How the data is used

Solely to produce answers and briefings for the account owner, in the owner's own Telegram chat. The data is not used for advertising, profiling, resale, or any purpose unrelated to the features described on the home page.

3. Where the data goes

  • The owner's own machine — the app runs there as a Docker container. Application logs stay local.
  • Anthropic — message text and any calendar details needed to answer are sent to Anthropic's Claude API to generate the response, and are handled under Anthropic's terms.
  • Telegram — carries the conversation between the owner and the app.
  • Supabase (hosted PostgreSQL) — stores the encrypted Google refresh token, per-session bookkeeping, and usage counters.

Google user data is not sold, and is not shared with anyone beyond the processors listed above, which act only to deliver the app's own features.

4. Storage and retention

  • Calendar events are fetched on demand and are not written to the database. They may appear briefly in the app's transient runtime files on the owner's machine, which are discarded when the container is rebuilt.
  • The Google refresh token is kept until access is revoked or the account entry is deleted.
  • Session and usage records contain bookkeeping (identifiers, counts, timestamps), not calendar content.

5. Security

The Google refresh token is encrypted with AES-256-GCM before being stored. The encryption key exists only as a file on the owner's machine, mounted read-only into the container. It is never placed in the database, in environment variables, or in the container image. The app exposes no inbound network ports.

6. Limited Use

ty-assistant's use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements.

7. Revoking access and deletion

Access can be withdrawn at any time at Google Account permissions, which immediately invalidates the stored token. To have the stored account entry and associated records deleted, contact the address below.

8. Children

The app is not directed at children and is used only by its owner.

9. Changes

If this policy changes, the effective date above is updated.
